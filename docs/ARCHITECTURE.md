# Архитектура

```text
routools/
  cli.py          argparse, текстовый и JSON-вывод
  dedupe.py       SHA-256, группировка, quarantine
  rename.py       план переименования, проверка коллизий, two-phase apply
  csv_report.py   чтение CSV, нормализация, счётчики
scripts/
  build_demo.py   тестовый сценарий и HTML-отчёт
tests/
  test_routools.py
```

## Почему так

### Сначала план, потом изменения

`dedupe` и `rename` по умолчанию ничего не меняют. Это снижает риск для клиентских файлов и делает результат проверяемым до `--apply`.

### Quarantine вместо удаления

Дубли перемещаются в отдельную папку. Если правило оказалось неверным, файлы можно вернуть. Удаление остаётся решением владельца данных.

### Two-phase rename

Переименование сначала уводит файлы во временные имена, затем выдаёт целевые. Это позволяет менять имена даже при пересечении старого и нового наборов.

### Без зависимостей

Для базовых задач достаточно стандартной библиотеки. Это упрощает запуск на машине клиента и уменьшает поверхность поставки.

## Границы

- Нет фонового демона и расписания.
- Нет облачных API и авторизации.
- Нет обработки `.xlsx`; для Excel нужен отдельный слой.
- Нет автоматического выбора правил: правила задаёт человек.
